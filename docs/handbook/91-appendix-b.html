B Checklists and decision tables

The operational half of the book: the thirty-five rules in one place, four checklists for the things that are done repeatedly, a triage table for when something breaks, and every configured value with the reasoning that produced it.

B.1   The rules, collected

Ch.Rule
1The model extracts and the model phrases. Code decides.
2Design as though the components around you will be replaced, because in a cascade they are.
3Keep three latency numbers: a target, an alert threshold, and a timeout. This project has only the third.
5Do not invent vocabulary for “a thing the call needs to collect”. Use slot, form, step, validator, confirmation, no-match.
6Extract once, store forever. A value changes only through an explicit correction, never by re-reading the transcript.
7A Verified slot has a constructor only the lookup code can reach. A model must never be able to write one.
8A step transition is a pure function of stored state. No model call, no network call, no clock.
10Write what must survive to durable storage before telling the caller it is done, and never make the caller wait on a third party.
12Order prompt layers most-static to most-volatile. Anything that changes per turn goes last, in the user message.
15Layer 5 is generated by code from state that code owns. Nothing in it is written by hand.
16Render the prompt's schema and the code's validator from the same manifest. Never maintain them side by side.
17Ask of every capability: if the caller could choose this one freely, what would it cost? That is the real authorisation model.
18Assemble and validate prompts at load; cache by (form, step); reload on a signal, not per turn.
18Log a hash of the assembled prompt on every turn. With hot reload, the file in git is not evidence of what ran.
21Re-derive max_tokens whenever a key is added to the schema, and record the measurement next to the value.
22Schemas must be stable and few, with a deterministic key order, so the number of distinct grammars equals the number of steps.
23A confidence threshold is a fitted parameter, valid for one (model, prompt, schema) triple. A prompt edit invalidates it.
25One error variant per distinct operator response, not per distinct code path.
27Order the output schema by when the value is needed. The caller's sentence first; everything code reads after.
28The inference timeout must be shorter than the caller's own timeout.
29Retry against a deadline, not a count. Attempt again only if there is time for it to be useful.
30Never return an error to a live call. Every failing path ends in a sentence in the caller's language.
33Confirm what is expensive to get wrong, and nothing else. Confirmation is a budget.
34The model emits structure; code renders speech. Read-back is a method on the value, per type.
35The re-prompt must differ from the prompt, and the third failure ends the attempt.
36Never make the caller re-authenticate after a transfer. Pass the authentication state forward.
39Percentiles, never means, for anything on the path to a caller's ear.
40Prompts and messages go in span events, not span attributes.
41Log the shape of the turn, not its contents. Slot names, not slot values.
43Mark sensitivity in the manifest, next to the type, and let it drive logging, retention and hand-off automatically.
44Every store that holds caller data carries an indexed call_id, and one function deletes a call from all of them.
45Build the disclosure before the first production call. One phrase per language, one flag on the session.
46Never treat the transcript as what the caller said. It is the recogniser's best guess.
48A value is confirmed only if the caller heard it read back.
49Do not build the audio layer. Keep the boundary at text in, sentence out.

B.2   Adding a slot

  • Declared in the form manifest: name, type, required, confirmation policy, sensitivity ch. 16, 43
  • A parser exists for its type, with unit tests for words and digits ch. 46
  • Domain validation on the type; business validation on the form — and they produce different sentences ch. 8
  • Read-back rendering implemented for its type, in every supported language ch. 34
  • Provenance decided: Verified, Collected or Inferred ch. 7
  • If Inferred: what recomputes it when its inputs change ch. 9
  • Included in the step's extraction schema and in the form-wide schema, so over-answering works ch. 9
  • max_tokens re-derived against the larger schema ch. 21
  • A scenario covers it, including one where the caller corrects it ch. 38
  • It appears on the hand-off card ch. 36
  • Its retention and deletion are covered by the existing paths ch. 44

B.3   Adding a key to the output schema

  • Decide which side of the line it is on. Read by a human → the flattened map. Drives a branch → the manifest, with a named field and a test ch. 16
  • Written as real JSON with quoted keys, in the prompt file prompts/README.md
  • Placed after humanlike_sentence_answer in schema order ch. 27
  • Token cost estimated; max_tokens re-derived ch. 21
  • The key-order test in vllm.rs updated, deliberately ch. 27
  • The scenario suite re-run — a schema change is a behaviour change ch. 38
  • If it will gate anything: calibrated first, not assumed ch. 23

B.4   Editing a prompt

  • Not against a production endpoint — every edit is a cache miss for every concurrent caller ch. 26
  • Nothing volatile moved towards the front ch. 26
  • The change addresses an observed failure, not an imagined one ch. 14
  • Sample phrases: are there now three of the same shape? ch. 13
  • The scenario suite run afterwards. A prompt edit is an untested deploy until it has been. ch. 38
  • Routing distribution checked for a shift ch. 39
  • Any confidence threshold fitted against the old prompt re-fitted ch. 23
  • Committed — hot reload means the running prompt can diverge from the repository silently ch. 18

B.5   Before the first real call

Ordered by what is hardest to retrofit.

  • Disclosure. Spoken, plain language, first interaction, naming the machine and on whose behalf. Logged ch. 45
  • Redaction boundary. Raw text lives for the turn; everything durable sees the redacted copy ch. 43
  • Log retention. ./logs rotates but never deletes; today's retention period is forever ch. 42, 44
  • The debug! that logs the model's full output is gated by level, and the level gets raised at 2 a.m. Make it a redacting type ch. 41
  • Deterministic fallback sentences exist, per language. Nothing may return an error to a call ch. 30
  • Timeout under the platform ceiling — but not before the fallback exists ch. 28, 30
  • Idempotency on the turn and a unique constraint on the submission ch. 28, 31
  • Session TTL in hours, not days ch. 10, 44
  • Erasure path that reaches every store, written before it is needed ch. 44
  • Hand-off works, carries the structured card, and does not re-authenticate ch. 36
  • Time-to-first-token and p95 turn time measured, not inferred ch. 3, 39
  • Ask the platform: end-of-turn silence threshold, webhook response ceiling, whether barge-in reports what was actually spoken ch. 47, 28, 48
  • sqlx::migrate! — still commented out in main.rs context.md

B.6   Incident triage

SymptomMost likely causeFirst thing to check
504, latency matches timeout_seconds exactly The client gave up; the server is slow, not down GPU contention and queue depth. Not container health ch. 25
502 with Transport Genuinely unreachable Container, LLM_URL, the compose network
502 with Truncated Our own cap. The schema outgrew it llm_settings.max_tokens — the message names it ch. 21
502 with Malformed Prompt or decoding mode Whether the schema is still valid JSON with quoted keys ch. 22
A badge vanished from the client The model renamed a key, or preserve_order was dropped The raw content in a debug log; then Cargo.toml ch. 16
The same question asked repeatedly; the caller is cooperating Slot name mismatch between prompt and validator Whether both come from one manifest. This is the Chapter 16 bug ch. 16
Escalations rose after a prompt edit Routing shifted; attempts now accumulate Routing distribution before and after; the prompt hash ch. 18, 39
Turn latency crept up with no code change Prefix cache hit rate collapsed Whether anything volatile moved forward in the prompt ch. 26
Callers talk over the agent p95 turn time past the budget; the timeout hides it p95, not the mean. Barge-in counts on the platform's side ch. 3, 39
A confirmed value turns out to be wrong Barge-in cut the read-back before that value was spoken Whether confirmation is set from generated or heard text ch. 48
Duplicate submissions Webhook retry; at-least-once is the guarantee The unique constraint on (call_id, payload_hash) ch. 28, 31
Log files are empty A RUST_LOG filter naming a crate that does not exist .env for duplicate RUST_LOG lines — the last wins context.md
Answers went strange after an editor save A half-saved prompt; the last good text is in use The warning line from SystemPrompt::current() ch. 18
