C Glossary

Terms as this book uses them, including the ones these two repositories invented. Where a word has a settled meaning in the task-oriented dialogue literature, that meaning is the one given.

active fields
(this project) The list of questions currently being worked through. Not always the form's own fields — a caller who chose to be looked up is asked identity questions first. ch. 11
at-least-once delivery
The guarantee every major webhook platform provides: an event will arrive, and may arrive more than once. Duplicates are the contract, not a defect. ch. 28
barge-in
The caller speaking while the agent is talking. Handling it means cancelling synthesis and reconciling the conversation record to what was actually heard. ch. 48
backchannel
“Mm-hm”, “right” — an acknowledgement spoken over the agent, not an attempt to take the floor. Not a barge-in. ch. 48
call session
(this project) Everything known about a call in progress: language, slots collected, which question is outstanding, attempts, the turn window. Lives in Redis and expires. ch. 10
cascade / cascaded pipeline
Speech recognition, then a language model, then speech synthesis, as separate components. The dominant production architecture, and the one this service is the middle of. ch. 2
constrained decoding
Masking tokens during generation so output cannot leave a grammar. In vLLM: json_object (valid JSON), guided_json (your schema), guided_choice (one of a list). ch. 22
containment
The share of calls resolved without a human. Meaningless without task completion beside it — refusing to escalate maximises it. ch. 39
dialogue state tracking (DST)
Deriving the current slot values from a conversation. A benchmarked task; see joint goal accuracy. ch. 6
endpointing
Deciding the caller has finished, from the transcript stream rather than from audio silence. Faster than waiting out a silence threshold; the recommended default. ch. 47
event / subscriber / dispatcher
(this project) A fact about the call, the code that asked to hear about it, and the thing that routes one to the other in priority order. The observer pattern applied to a call flow. ch. 11
flow
(this project) The form currently being filled in, if any. Lives on the call session. ch. 11
form
A group of slots collected together. VoiceXML's word, and every subsequent system's. Dialogflow CX calls it a page. ch. 5
Form Interpretation Algorithm (FIA)
VoiceXML's procedure for visiting each unfilled field until the form is complete. The algorithm every slot-filling implementation converges on. ch. 5
implicit confirmation
Reading a value back inside the next question, so the caller can object without being required to agree. Costs no turns. The default. ch. 33
joint goal accuracy
The fraction of turns at which every slot is simultaneously correct. 25.65% for the best tracker on SpokenWOZ — the number behind Chapter 6's central rule. ch. 6
layer (prompt)
(this book) One of six bands of prompt content ordered by how often it changes, from identity (layer 0) to per-turn runtime state (layer 5). ch. 12
manifest
(this book) The single definition of a form's slots, types, validators and prompts, from which both the prompt's schema text and the code's validators are rendered. ch. 16
mixed initiative
The caller may answer several fields at once, in any order, without waiting to be asked. VoiceXML's term. ch. 9
no-input / no-match
Silence, and speech that could not be understood. Two different failures needing two different responses. Three of either ends the attempt. ch. 35
pass-through map
(this project) ActionDecision's flattened serde_json::Map, carrying every schema key except the one the code names. Makes schema keys free to add, and invisible to the compiler. ch. 1, 16
prefix cache
vLLM's reuse of attention state for a shared prompt prefix. Cached in 16-token blocks; keyed from position zero; worth 60–80% of time to first token when it hits. ch. 26
provenance
(this book) Where a slot's value came from: Verified (an authoritative source), Collected (the caller), Inferred (computed). The distinction that separates a bug from a data-protection incident. ch. 7
repair prompt
Re-asking the model with its malformed output and the parser's complaint attached. Rung 2 of the degradation ladder; at most once, inside the budget. ch. 30
slot
One thing the call needs to collect. VoiceXML's field item variable, Dialogflow's parameter. Here: a name, a typed value, a raw string, provenance, a confirmation flag and an attempt count. ch. 7
stage
(this project) Where a call is inside a form: confirming the start, collecting field N, confirming field N, reviewing the summary. ch. 11
step predicate
(this book) filled && valid && (!needs_confirm || confirmed), evaluated in code over stored state. Never asked of the model. ch. 8
time to first token (TTFT)
How long until generation begins. The figure comparable to the 375 ms model-stage budget, and the one this project does not currently measure. ch. 3, 39
turn
One request and one response — the caller said something, the system said something back. The unit everything in this book is measured in.
turn window
(this book) A fixed-length ring of the last four to six turns, rendered into layer 5. Evidence for reference resolution, never a source of state. ch. 6, 15
VAD (voice activity detection)
Classifying audio frames as speech or silence. The simplest turn-detection method and the slowest, because it waits out the full silence threshold every turn. ch. 47
warm transfer
Handing a call to a human with a briefing first, carrying a structured card rather than a free-form summary — and without re-authenticating the caller. ch. 36
workflow (vs. agent)
Models and tools orchestrated through predefined code paths, as against a model directing its own process. This system is a workflow — routing, plus prompt chaining across steps. ch. 4
